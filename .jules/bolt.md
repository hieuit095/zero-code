## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.
## 2024-05-08 - File Explorer Re-render Bottleneck
**Learning:** In `FileExplorer.tsx`, recursive file tree structures suffer from an O(N) re-render penalty on every active tab change. If `selectedId` is passed down globally, standard `React.memo()` is ineffective because it attempts a shallow equality check which prevents event propagation. Crucially, branch nodes (folders) *must always re-render* to propagate new selection states down the tree; only leaf nodes (files) can be safely memoized using a custom `arePropsEqual` function that compares derived selection state.
**Action:** When memoizing recursive tree components that receive globally active IDs, explicitly return `false` from the custom equality function for branch nodes, and only apply shallow comparisons and derived state checks to leaf nodes to achieve O(1) performance without functional regressions.
