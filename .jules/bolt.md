## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.

## 2024-06-23 - File Tree Re-render Bottleneck
**Learning:** In `FileExplorer.tsx`, passing a globally active `selectedId` down a recursive file tree caused every node to re-render whenever the selection changed, leading to O(N) rendering performance. Standard `React.memo` fails because it does a shallow comparison of props, and `selectedId` changes frequently.
**Action:** Use `React.memo()` with a custom `arePropsEqual` function for the recursive node component. Critically, folders (branch nodes) must always return `false` in `arePropsEqual` to ensure prop propagation, while files (leaf nodes) can be memoized by checking if they were the previously selected node or the newly selected node. Always pair this with `useCallback` for functions passed down the tree (like `onSelect`).
