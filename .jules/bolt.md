## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.

## 2024-05-15 - Recursive Component Re-render Bottleneck (File Tree)
**Learning:** In recursive tree components like `FileExplorer.tsx`, passing a globally active ID (e.g., `selectedId`) down to every node causes the entire O(N) tree to re-render whenever the active item changes. Wrapping the recursive node in `React.memo()` mitigates this, but *only* if the callback props are also strictly stable. Furthermore, when memoizing recursive components, using a named function expression matching the wrapper (e.g. `const Comp = memo(function Comp(...) { return <Comp /> })`) causes recursive calls to bind to the *unmemoized* inner function locally, defeating the optimization entirely.
**Action:** Use a distinct internal name for the inner function of memoized recursive components (e.g. `const FileRow = memo(function FileRowInner(...)`) and wrap injected callbacks (like `onSelect`) in `useCallback()` to successfully achieve an O(1) render cost when an active ID changes.

## 2024-05-15 - React.memo Shallow Comparison vs Globally Changing Props
**Learning:** We attempted to optimize `FileExplorer.tsx` using `React.memo()`. However, `selectedId` was passed down to all nodes. A shallow comparison of `selectedId` (e.g., `'file-A'` to `'file-B'`) will evaluate to `false` for every single node in the tree, completely bypassing the memoization and resulting in an O(N) re-render.
**Action:** When passing a globally changing ID down to memoized children, `React.memo` requires a custom equality function (e.g., `arePropsEqual`) that explicitly checks whether the specific node's derived selection state actually changed (e.g., `wasSelected === isSelected`), allowing for true O(1) rendering costs.
