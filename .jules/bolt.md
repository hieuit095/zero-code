## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.
## 2024-05-24 - FileExplorer Recursive Rendering
**Learning:** In a highly recursive file tree architecture with active selection states passed down as props (`selectedId`), standard `React.memo` is completely ineffective for branch nodes (folders) because they must always be able to propagate selection state changes down to their deeply nested children. If a folder is memoized based on its own selection state, selecting a nested child will never reflect in the UI because the parent folder bails out of rendering.
**Action:** When optimizing recursive tree structures, apply `React.memo` with a custom `arePropsEqual` function that explicitly forces branch nodes (e.g., folders) to ALWAYS re-render (`if (nextProps.node.type === 'folder') return false;`). Strict O(1) equality checks should only be applied to leaf nodes (files) to ensure rendering bail-outs do not break tree state propagation.
