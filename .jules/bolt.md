## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.

## 2024-05-09 - File Tree O(N) Re-render Bottleneck
**Learning:** In `FileExplorer.tsx`, selecting a new file updated `activeTabId`, causing every folder and file node in the recursive `FileRow` tree to unnecessarily re-render (an O(N) cost) because the standard component didn't use memoization. Additionally, a naive `React.memo()` wrapper doesn't work correctly for recursive tree views: branch nodes (folders) must *always* re-render to successfully propagate new props (like `selectedId`) down to their leaf children.
**Action:** When memoizing recursive components, implement a custom `arePropsEqual` comparator that always returns `false` for folder nodes, but returns `true` for file nodes if their specific selection state (derived from `selectedId`) hasn't changed. Also, always ensure the callback functions passed down the tree (like `onSelect`) are wrapped in `useCallback` to prevent breaking the memoization.
