## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.

## 2024-05-25 - File Explorer Re-render Bottleneck
**Learning:** When passing a globally active ID (like `selectedId`) down a recursive tree component (like `FileRow` in `FileExplorer`), standard `React.memo()` shallow comparison fails to provide O(1) updates. Furthermore, if a component's internal function name matches its variable assignment (e.g., `const FileRow = memo(function FileRow(...)`), recursive calls bind to the internal, un-memoized function instead of the wrapped `memo` version, completely bypassing the optimization.
**Action:** When memoizing recursive components, ensure the inner function has a distinct name (e.g., `function FileRowComponent`). To achieve O(1) re-renders for global state props, provide a custom `arePropsEqual` function where branch nodes (folders) *always re-render* (return `false`) so they can successfully propagate the prop down, and only memoize leaf nodes (files) based on strict derived state evaluation (e.g., `isSelected = selectedId === node.id`).
