## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.

## 2024-05-13 - File Tree Recursive Re-render Bottleneck
**Learning:** In `FileExplorer.tsx`, the `FileRow` component was recursively rendering the entire virtual file system tree on every state change (e.g., when a single file's `selectedId` updated). Because it wasn't memoized, toggling a single file selection forced O(N) reconciliations across all files and folders. Standard `React.memo` fails here because passing a globally active ID (`selectedId`) to all nodes triggers shallow inequality. To achieve O(1) leaf re-renders, a custom `arePropsEqual` function must be provided. Crucially, branch nodes (folders) *must always re-render* (return `false`) to correctly propagate the new `selectedId` down to their children. Only leaf nodes (files) can be safely memoized.
**Action:** When passing globally active state down a recursive React tree, wrap the recursive component in an anonymous function within `React.memo` (to avoid local name shadowing recursion bugs) and provide a custom `arePropsEqual` function that forcefully re-renders branch nodes while strictly memoizing leaf nodes based on specific state changes.
