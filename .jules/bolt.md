## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.

## 2024-04-04 - React Memoization on Recursive Trees
**Learning:** Standard `React.memo()` shallow comparison fails on recursive components (like a File Tree) if a globally active prop (e.g., `selectedId`) is passed down, causing O(N) re-renders across the entire tree. Additionally, if you memoize branch nodes (folders), they will block the `selectedId` prop from reaching their children if the branch itself didn't change. Also, when memoizing recursive components, using a named function expression matching the wrapper name causes the inner recursive calls to use the unmemoized original function.
**Action:** To achieve O(1) leaf-node re-renders in recursive trees, use a custom `arePropsEqual` function that explicitly forces branch nodes to always re-render (return `false`), while only comparing the `selectedId` against the specific node's ID for leaf nodes. Rename the inner component before passing it to `memo` to avoid "same name" recursion bypassing.
