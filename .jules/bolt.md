## 2024-04-03 - Agent Chat Re-render Bottleneck
**Learning:** In `AgentChatter.tsx`, high-frequency WebSocket streaming events (e.g., token-by-token LLM output) caused the entire message history to re-render. Because the `messages` array was mapped inline, every incoming token triggered a full DOM reconciliation for all historical chat bubbles, resulting in an O(N) render cost that degraded performance linearly as the chat lengthened.
**Action:** Always extract items mapped in high-frequency update loops (like streaming logs or chat tokens) into separate components wrapped in `React.memo()`. This creates an O(1) rendering cost where only the actively changing item re-renders, preventing UI stuttering and wasted CPU cycles.

## 2024-05-18 - File Tree Global State Re-render Bottleneck
**Learning:** In `FileExplorer.tsx`, the `activeTabId` is a global string passed down as a prop to every node in a recursive file tree component (`FileRow`). Because the default React component behavior re-renders on any prop change, changing the active tab triggered a full O(N) re-render of every single file and folder in the entire tree. Furthermore, standard `React.memo()` shallow comparison fails because the recursive tree structure makes it difficult to correctly memoize branch nodes.
**Action:** When passing globally active state down a recursive tree, achieve O(1) re-renders by wrapping the component in `React.memo()` with a custom `arePropsEqual` function. Crucially, always return `false` for branch nodes (folders) so they re-render and successfully propagate the updated props down to their children, and only return `true` for leaf nodes (files) if their specific active state has not changed. Additionally, use `useCallback` for event handlers passed down the tree.
